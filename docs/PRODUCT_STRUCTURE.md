# ZhuzhuPig 云相册产品结构 V2.1

## 1. 产品不是“网页相册”，而是两套界面

### A. 对外摄影展厅
- 公开主页
- 公开图册
- 单图册分享链接
- 口令图册
- 原比例作品浏览
- 流式 / 缩略图 / 大图模式
- 全屏灯箱

### B. 私人云图库
- 管理员登录
- 一级文件夹
- 二级文件夹
- 图册
- 照片
- 标签
- 批量导入桌面文件夹
- 图册权限
- 设置封面
- 多选 / 批量删除
- 缩略图 / 列表管理模式

## 2. 层级模型

```text
私人云图库
├── 一级文件夹
│   ├── 二级文件夹
│   │   ├── 图册
│   │   │   ├── Photo 001
│   │   │   ├── Photo 002
│   │   │   └── ...
│   │   └── 图册
│   └── 图册
└── 图册
```

为什么限制为两级文件夹：个人摄影库如果无限嵌套，很快会变成传统网盘；两级目录之后进入图册，更适合摄影项目与作品集管理。

## 3. 文件夹批量导入规则

桌面目录：

```text
摄影作品/
  日本/
    东京/
      夜景/
        001.jpg
        002.jpg
```

云端最多保留两级管理文件夹，剩余路径合并为图册名：

```text
日本（一级文件夹）
└── 东京（二级文件夹）
    └── 夜景（图册）
```

如果在二级文件夹中继续导入更深目录，则更深路径会进入图册名，而不是继续无限嵌套。

## 4. 图片文件模型

每张照片有三份用途不同的文件：

1. Original：原始上传文件，R2 私有存储。
2. Preview：约 2200px，用于正常图册浏览。
3. Thumbnail：约 640px，用于缩略图墙、封面与管理后台。

这样可以避免浏览 100 张图时直接加载 100 张 10–30MB 原图。

## 5. 权限模型

- Public：公开主页可见。
- Unlisted：主页隐藏，只有拿到图册链接的人可看。
- Password：图册链接 + 访问口令。
- Private：只有管理员登录后可看。

文件夹不直接决定权限，权限以图册为单位，避免一个父目录权限误操作导致整批私人照片外泄。

## 6. 成熟产品参考逻辑

### Google Photos
吸收：图册封面、排序、批量照片组织、以“集合/图册”为核心而不是只按磁盘目录管理。

参考：
https://support.google.com/photos/answer/6128849

### Dropbox
吸收：Grid / Large Grid / List 这种针对大量文件的多视图管理思路。

参考：
https://help.dropbox.com/organize/sort-files

### Pixieset Client Gallery
吸收：Folder → Collection 的摄影业务组织模式，以及“桌面文件夹批量创建摄影集合”的工作流。

参考：
https://help.pixieset.com/hc/en-us/articles/31178129650957-Using-folders-to-share-and-organize-galleries
https://help.pixieset.com/hc/en-us/articles/41219071036685-Bulk-creating-collections-in-Client-Gallery

## 7. 后续推荐顺序

P1：稳定核心存储
- 上传断点/失败重试
- 回收站
- 重复文件检测
- 照片移动到其他图册
- 拖拽排序

P2：摄影信息管理
- EXIF 展示
- 拍摄日期 / 相机 / 镜头筛选
- 地点
- 星标精选
- 色彩标签

P3：交付与分享
- 访客收藏照片
- 禁止/允许原图下载
- 分享链接有效期
- 指定访客授权
- 水印
- 下载 ZIP

P4：作品集策展
- 多个“主页”
- 从多个图册挑选作品组成专题
- 自定义封面、顺序、标题和说明
- 独立专题分享链接
