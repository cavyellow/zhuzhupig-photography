# ZhuzhuPig Photography · Private V2.1

这是一个独立于 Floot 的私人摄影云图库源码版本，面向 GitHub + Cloudflare Workers / D1 / R2 部署。

## 这一版的产品结构

对外访问与内部管理分开：

- `/`：公开摄影作品主页，只列出 `public` 图册。
- `/album/:id`：单独图册页面，可用于分享。
- `/manage`：管理员私人云图库。
- `/folder/:id`：管理员文件夹层级页面。

私人云图库采用：

`云图库 → 一级文件夹 → 二级文件夹 → 图册 → 照片`

文件夹只是管理层级，不自动公开。真正的外部访问权限仍然以“图册”为单位。

## 图册权限

- `public`：出现在公开主页，任何人可浏览。
- `unlisted`：不出现在公开主页；拿到图册链接的人可以浏览。
- `password`：需要图册链接 + 访问口令。
- `private`：仅管理员登录后可浏览。

新建图册默认 `unlisted`，降低误公开风险。

## V2.1 新增能力

### 1. 文件夹与二级目录

管理后台支持最多两级文件夹。例如：

```text
云图库
├─ 2026
│  ├─ 日本
│  │  ├─ 东京夜行（图册）
│  │  └─ 京都秋日（图册）
│  └─ 青岛（图册）
└─ 客户项目
   └─ Client A
      └─ Campaign 01（图册）
```

### 2. 批量导入电脑文件夹

管理后台点击“导入文件夹”，可以选择整个桌面文件夹。浏览器会读取 `webkitRelativePath` 并自动生成管理结构。

示例：

```text
摄影作品/
  日本/
    东京夜行/
      001.jpg
      002.jpg
    京都秋日/
      001.jpg
```

导入后：

```text
日本（一级文件夹）
├─ 东京夜行（图册）
└─ 京都秋日（图册）
```

如果目录超过两级，超过的路径会合并进图册名称，避免无限嵌套。

### 3. 原图 + Web 预览图 + 缩略图

每张照片上传时，浏览器会自动生成：

- 原图：保存在 R2，用于灯箱查看与未来原图下载。
- 预览图：最长边约 2200px，适合普通作品浏览。
- 缩略图：最长边约 640px，适合大量照片快速浏览。

R2 中原图和衍生图分目录保存，D1 只保存文件关系和元数据。

### 4. 图册三种浏览模式

- **流式**：保持照片原始宽高比，类似摄影作品墙。
- **缩略图**：密集方形网格，适合快速找片。
- **大图**：单列完整比例浏览。

浏览模式会保存在浏览器本地，下次访问保持上次选择。

### 5. 灯箱与管理

点击照片进入黑色全屏灯箱：

- 保持原始比例 `object-fit: contain`。
- 左右翻页。
- 键盘方向键翻页，Esc 关闭。
- 管理员可将当前照片设为图册封面。

### 6. 批量照片管理

管理员进入图册后可以：

- 批量追加上传。
- 进入选择模式。
- 多选照片。
- 批量删除，删除时同步清理 R2 原图、预览图和缩略图。

## 手机端适配

V2.1 重新调整了手机端：

- 图册照片不再统一强制裁切成长方形。
- 流式模式按照片真实比例显示。
- 手机缩略图模式为 3 列方格，用来快速找图。
- 大图模式为完整单列，不裁切主体。
- 图册标题字号、顶部导航、筛选工具条和管理按钮都针对 320–620px 宽度重新处理。
- 公开首页图册卡片在手机上使用 3:4，比桌面 4:5 更紧凑。

## 技术架构

```text
GitHub 私有仓库
   │
   └─ Cloudflare Workers + Static Assets
         ├─ public/          前端网页
         ├─ src/worker.ts    API、登录、图册权限
         ├─ D1              文件夹 / 图册 / 照片元数据
         └─ R2              原图 / preview / thumbnail
```

照片文件不放 GitHub。GitHub 保存源码和版本历史；R2 才是摄影文件存储空间。

## 数据表

- `folders`：一级、二级文件夹。
- `albums`：图册及分享权限。
- `photos`：原图、预览图、缩略图和照片尺寸。

Worker 启动时会自动检查基础表和 V2.1 新字段，因此从早期 V2 数据库升级时也能补齐新增列。`migrations/0001_init.sql` 同时保留完整结构，方便手动初始化或审计。

## 本地运行

```bash
npm install
npx wrangler login
npm run dev
```

如果你手动创建 D1，也可以运行：

```bash
npm run db:local
```

## Cloudflare 配置

项目需要：

- D1 binding：`DB`
- R2 binding：`PHOTOS`
- Static Assets binding：`ASSETS`
- Secret：`ADMIN_PASSWORD`
- Secret：`SESSION_SECRET`

Secret 不要提交到 GitHub。

```bash
npx wrangler secret put ADMIN_PASSWORD
npx wrangler secret put SESSION_SECRET
```

`SESSION_SECRET` 建议使用随机长字符串。

## 部署

```bash
npm run deploy
```

也可以将本仓库连接到 Cloudflare 的 GitHub 部署流程。正式部署后建议绑定自己的域名，例如 `photo.zhuzhupig.com`。
